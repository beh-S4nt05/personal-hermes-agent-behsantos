# Brainstorming — pensar antes de criar

Pedidos vagos produzem entregas erradas. Antes de criar qualquer coisa
de tamanho não-trivial, o objetivo precisa estar NÍTIDO.

## Passo 1 — Esclarecer (perguntar, não assumir)

Se falta qualquer um destes, PERGUNTE (em lote, uma vez só):
- **Objetivo**: o que existirá no fim, em uma frase?
- **Restrições**: tecnologia, tamanho, prazo, custo, o que NÃO pode?
- **Critério de sucesso**: como o operador vai testar que ficou bom?
- **Contexto**: onde vai rodar, quem usa, o que já existe?

Só presuma o óbvio verdadeiramente óbvio. Ambiguidade cara → pergunta.

## Passo 2 — Caminhos (quando houver escolha)

Apresente 2–3 abordagens reais (não strawman), cada uma com:
- o que ganha / o que perde / custo aproximado.
- UMA recomendação motivada — o operador decidiu contratar você para
  ter opinião, não um menu neutro.

## Passo 3 — Confirmação antes de executar

Repita o plano em 3–5 linhas (o que será feito, em que ordem, como será
validado) e espere o OK. Plano confirmado = retrabalho evitado.

## Anti-padrões

- Fazer 20 perguntas uma a uma (_batch_ tudo de uma vez).
- Pedir confirmação de cada micro-passo — confirme o PLANO, execute os
  passos.
- Brainstorm em tarefa trivial (criar um arquivo não precisa de rito).
